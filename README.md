# Синтез метана Сабатье — фронтенд

Одностраничное приложение для работы с материалами реакции Сабатье
(CO₂ + 4H₂ → CH₄ + 2H₂O). Материал реакции — это услуга системы, то есть
исходное вещество для синтеза метана: водород, углекислый газ, вода, биогаз,
катализатор.

Курс «Разработка Интернет Приложений», МГТУ им. Н. Э. Баумана, ИУ5, осень 2026.

Лабораторная 6: содержимое страниц приходит из веб-сервиса, обращения к домену
услуг идут через Redux Toolkit с middleware redux-thunk и сгенерированный
из Swagger код axios, добавлены аутентификация и страница добавления материала.

## Запуск

Нужен Node.js 22 или новее — вместе с ним ставится npm.

```bash
npm install      # поставить библиотеки из package.json
npm run dev      # https://localhost:3000
```

| Команда | Что делает |
|---|---|
| `npm install` | ставит все библиотеки в `node_modules` |
| `npm run dev` | сервер разработки с горячей заменой модулей, https на 3000 порту |
| `npm run generate-api` | кодогенерация клиента axios: семь методов домена «Материал» |
| `npm run build` | сборка для развёртывания, результат в `dist` |
| `npm run preview` | локальный просмотр собранной версии |

Бэкенд из соседнего репозитория `Synthesis-Sabatie-backend` запускается отдельно:

```bash
docker compose up -d    # MinIO :9000, Postgres :5434, Redis :6379, Adminer :8082
source synthesis-sabatie/bin/activate
python main.py          # http://127.0.0.1:8000, swagger на /docs
```

Без запущенного бэкенда плитка и лента работают на коллекции mock-объектов —
но только для гостя.

## Кодогенерация клиента из Swagger

Бэкенд описывает контракт спецификацией OpenAPI на `/openapi.json`. Клиент
к этому контракту не пишется руками, а генерируется:

```bash
npm run generate-api        # бэкенд должен быть запущен
```

Скрипт `scripts/generate-api.mjs` вызывает `swagger-typescript-api`
с `httpClientType: "axios"` и складывает результат в `src/api/Api.ts`:
типы всех тел запросов и ответов плюс класс `Api` с методами веб-сервиса.

FastAPI собирает `operationId` из имени обработчика, пути и метода —
`get_sabatier_materials_api_sabatier_materials_get`. Хук `onFormatRouteName`
оставляет от него только имя обработчика, поэтому методы клиента названы
по предметной области, а `moduleNameIndex: 1` раскладывает их по доменам:

| Метод веб-сервиса | Сгенерированный метод клиента |
|---|---|
| `GET /api/sabatier_materials` | `api.sabatierMaterials.getSabatierMaterials` |
| `GET /api/sabatier_materials/feed` | `api.sabatierMaterials.getSabatierMaterialFeed` |
| `GET /api/sabatier_materials/draft` | `api.sabatierMaterials.getSabatierMaterialDraft` |
| `POST /api/sabatier_materials` | `api.sabatierMaterials.createSabatierMaterial` |
| `PUT /api/sabatier_materials/{id}/publish` | `api.sabatierMaterials.publishSabatierMaterial` |
| `DELETE /api/sabatier_materials/{id}` | `api.sabatierMaterials.deleteSabatierMaterial` |
| `POST /api/sabatier_materials/{id}/like` | `api.sabatierMaterials.likeSabatierMaterial` |

Генерируются ровно эти **семь** методов — весь домен «Материал». Домен
«Инженер-технолог» в генератор не попадает: скрипт выбрасывает из спецификации
все пути, кроме `/api/sabatier_materials`, и считает, сколько методов осталось.
Вход и выход пишутся вручную обычным axios, поэтому генерировать их незачем.

Типы `SabatierMaterialOut`, `ChemistUserOut` и остальные берутся оттуда же:
схемы `components.schemas` генерируются целиком, поэтому типы домена
пользователя доступны и написанному вручную коду. Своих копий интерфейсов
бэкенда в проекте нет.

## CORS и обратный прокси

Фронтенд живёт на `https://localhost:3000`, бэкенд — на `127.0.0.1:8000`.
Это разные источники, и браузер по умолчанию такой запрос не пропустит.

Ограничение снимается **проксированием**, а не заголовками на бэкенде:
в `vite.config.ts` всё, что начинается с `/api`, Vite пересылает на FastAPI.
Для браузера запрос остаётся запросом к своему же источнику, поэтому
проверки CORS не срабатывают, а кука `session_id` ходит как своя.

Тем же способом снимается смена источника для хранилища S3: прямой адрес
MinIO — это `localhost:9000`, то есть снова другой источник. Поэтому у прокси
**второй маршрут**, `/s3`: префикс срезается, дальше идёт путь
`/<бакет>/<имя объекта>`. В Network обе группы запросов уходят на один адрес
`https://localhost:3000`.

Сервер разработки поднят по **https**: за это отвечает `@vitejs/plugin-basic-ssl`,
он сам выпускает самоподписанный сертификат при первом запуске. Браузер один раз
покажет предупреждение о сертификате — его нужно принять. На бэкенд и в MinIO
Vite ходит уже по http, это его собственное соединение, браузер его не видит.

```ts
plugins: [react(), basicSsl()],
server: {
  port: 3000,
  proxy: {
    "/api": { target: "http://127.0.0.1:8000", changeOrigin: true },
    "/s3": {
      target: "http://127.0.0.1:9000",
      changeOrigin: true,
      rewrite: (path) => path.replace(/^\/s3/, ""),
    },
  },
}
```

Кука выдаётся с флагом `HttpOnly`, прочитать её из JavaScript нельзя — браузер
прикладывает её сам, если у запроса стоит `withCredentials`. Он задан один раз
при создании клиента в `src/api/index.ts` и отдельно в запросах аутентификации.

## Глобальное хранилище

Три состояния, названные по предметной области.

| Слайс | Что хранит |
|---|---|
| `sabatierMaterials` | материалы плитки, материал ленты, значение фильтра и применённое значение, признак работы на mock-объектах, флаг запроса, текст ошибки |
| `materialDraft` | черновик текущего пользователя, флаг запроса, текст ошибки |
| `chemistUser` | логин, ФИО, признак модератора, признак аутентификации, флаг запроса, текст ошибки |

Фильтр лежит в хранилище, поэтому не теряется при переходе на ленту и обратно,
а при выходе из системы сбрасывается действием `materialFilterReset`.

### Домен услуг — через redux-thunk

Запросы к материалам вынесены из компонентов в middleware: компонент только
отправляет действие, а запрос выполняет `createAsyncThunk` сгенерированным
кодом. Жизненный цикл `pending` / `fulfilled` / `rejected` обрабатывается
в `extraReducers`.

```ts
export const getSabatierMaterials = createAsyncThunk(
  "sabatierMaterials/getSabatierMaterials",
  async (_, { getState, rejectWithValue }) => {
    const state = getState();
    try {
      const response = await api.sabatierMaterials.getSabatierMaterials({
        min_reaction_value: state.sabatierMaterials.appliedReactionValue,
      });
      return response.data;
    } catch {
      return rejectWithValue(guestMaterialsFallback(state, ...));
    }
  },
);
```

### Домен инженера-технолога — только axios

Аутентификация и деавторизация в middleware не заворачиваются: запрос
выполняется обычным `axios` прямо в компоненте, а в хранилище уходит уже
готовое действие. В `chemistUserSlice` поэтому только `reducers`
и ни одного `extraReducers`.

```tsx
const response = await axios.post<ChemistUserOut>(
  "/api/chemist_users/login",
  { chemist_login, chemist_password },
  { withCredentials: true },
);
dispatch(chemistUserLoggedIn(response.data));
```

### Почему сессии нет в Local Storage и Session Storage

Сессия серверная: она лежит в Redis, а браузеру достаётся только её
идентификатор в куке `session_id` с флагами `HttpOnly`, `Path=/`,
`SameSite=lax` и `Max-Age=3600`. `HttpOnly` означает, что куки нет
в `document.cookie` — JavaScript не может её ни прочитать, ни записать,
значит и положить её в `localStorage` или `sessionStorage` неоткуда.
Приложение туда не пишет вообще ничего, и это правильно: токен, доступный
скрипту, уводится любым XSS, а `HttpOnly`-кука — нет.

Во вкладке Application она лежит не в Local Storage, а в
**Cookies → `https://localhost:3000`**: прокси делает ответ бэкенда ответом
своего же источника, поэтому кука и записывается на адрес фронтенда. Оттуда её
значение копируется в Postman, чтобы повторить запрос плитки от имени
пользователя.

### Что происходит по F5

После перезагрузки страницы хранилище собирается заново из `initialState`,
то есть интерфейс возвращается в состояние гостя, хотя кука `session_id`
в браузере остаётся — это и показывается во вкладке Application.

### Анимация на время запроса

Пока любой из трёх слайсов держит `loading`, страницу перекрывает
`BlockingLoader` — он лежит поверх содержимого и навигационной панели,
поэтому ни одна кнопка в это время не нажимается.

## Коллекция mock-объектов

Если веб-сервис недоступен, thunk попадает в `rejected`, и данные берутся
из `src/modules/mock.ts`. Подмена работает **только для гостя**: у
аутентифицированного пользователя в коллекции mock-объектов нет ни своих
материалов, ни лайков, ни черновика, поэтому ему вместо подмены показывается
сообщение о недоступности сервиса.

В шапке приложения в режиме mock написано «Гость · данные из mock-объектов».

В терминале Vite при этом печатает `http proxy error: ... ECONNREFUSED
127.0.0.1:8000` на каждый запрос. Это не поломка, а штатный ход подмены:
прокси не достучался до веб-сервиса, ответил `500`, axios отклонил обещание,
thunk попал в `rejected` и взял данные из коллекции. Именно так снимаются
скриншоты 1–2 «Порядка показа» — страницы с mock без запущенного сервиса.
Сообщения пропадают сами, как только поднят бэкенд.

Запросов в логе вдвое больше, чем кажется (`x2`): в режиме разработки
`StrictMode` намеренно вызывает эффекты дважды. В сборке этого нет.

## Страницы приложения

Макет рассчитан на экран телефона 390 × 693 — формат 9:16. Снизу закреплена
навигационная панель из четырёх пунктов: Лента, Добавление, Плитка,
Вход/Выход. Гостю пункт «Добавление» недоступен, четвёртый пункт у него —
«Вход», у аутентифицированного пользователя — «Выход».

### Плитка материалов — `/`

Карточки опубликованных материалов в два столбца. Над ними фильтр по
минимальному значению для типовой реакции: ползунок, «Применить», «Сбросить»
и число найденных материалов. Отбор выполняет бэкенд — значение уходит
в запрос query-параметром `min_reaction_value`.

На карточке — изображение из MinIO, значение `min_reaction_value` плашкой
и счётчик лайков. Аутентифицированному пользователю счётчик работает кнопкой
лайка, а на своих материалах (`is_mine = 1`) появляется кнопка удаления.
Щелчок по карточке открывает материал в ленте.

### Лента — `/feed` и `/feed/:id`

Один материал поверх вертикального короткого видео из MinIO: название,
раскрывающееся описание, оба поля по предметной области, лайк и «Далее».
Следующий материал ищет бэкенд запросом с `next=true` — ид в базе могут идти
с пропусками, а за последним материалом лента возвращается к первому.

### Добавление материала — `/draft`

Страница создателя, гостя она отправляет на страницу входа. Работа идёт
в два шага, как устроен веб-сервис:

1. **«Далее»** — название материала и файлы изображения и видео. Выбранное
   изображение сразу показывается на странице. Создаётся черновик, файлы
   уходят в MinIO, в БД сохраняются только их имена. Без файлов остаются
   медиа по умолчанию.
2. **«Опубликовать»** — краткое описание, минимальное значение для реакции
   и молярная масса. Черновик становится материалом каталога.
   **«Удалить»** убирает черновик логически, сменой статуса.

Статус материала в интерфейс не выводится — это разные окна.

### Аутентификация — `/login`

Логин, пароль и «Войти». После успешного входа приложение переключается
в интерфейс пользователя и перечитывает плитку — теперь с его признаками
`is_mine` и `is_liked`.

Регистрации в приложении нет: по заданию страниц четыре, а в навигационной
панели переключается Вход/Выход. `POST /api/chemist_users/register` остаётся
методом веб-сервиса и показывается в Postman, как требует ЛР3.

Логины для показа берутся из `sql/02_seed_data.sql` бэкенда,
например `a.karpov` / `karpov_2026`.

## Медиафайлы

Бэкенд отдаёт имена файлов, а не ссылки: `material_image_name`,
`material_video_name`. Ссылку собирает фронтенд — объекты лежат в MinIO,
бакет `sabatie-assets` на порту 9000, доступ к нему публичный на чтение.

Ссылка собирается на маршрут прокси, а не на порт 9000:
`/s3/sabatie-assets/hydrogen.jpeg`. Так и AJAX, и медиа идут через свой
источник, `https://localhost:3000`, а бакет и имя объекта всё равно видны
в Network. Собирает её `src/modules/media.ts`.

Медиа по умолчанию `default_material.png` и `default_material.mp4` в MinIO
нет — по требованию методички оба файла лежат в самом проекте React,
в папке `public`. Туда же сложены копии материалов коллекции mock-объектов:
они нужны, когда бэкенд и MinIO не запущены.
